The purpose of this story is to create a distinct testing and validation pathway for the SAML integration component within the API Gateway. The primary goal is to ensure all aspects of SAML-based single sign-on (SSO) functionalities are correctly validated and robust against erroneous authentication attempts. 
Acceptance criteria include the system's ability to handle erroneous authentication requests gracefully, as specified. This story is primarily concerned with testing scenarios and is not intended to modify existing business logic or functionality of SAML integration. It depends on the AuthController and associated error handling mechanisms.
