## API Route Inventory and Audit
- Route inventory: See docs/ROUTE_INVENTORY.md for the current list of HTTP routes exposed by the API Gateway.

- What the automated guardrails check:
  - Routes: Reflection-based tests enumerate controller/action routes and assert that no payment- or webhook-related endpoints exist (keywords such as payment, billing, checkout, invoice, refund, transaction, wallet, subscription, webhook, callback).
  - Dependencies: Tests scan ApiGateway.csproj package references to ensure no payment/webhook SDKs are referenced (providers like stripe, paypal, braintree, square, razorpay, adyen, etc.).

- How to run the audit guardrails locally:
  - From the repository root, run:
    - dotnet test

- CI behavior:
  - The build will fail if prohibited routes or packages are introduced, enforcing the audit guardrails in continuous integration.
