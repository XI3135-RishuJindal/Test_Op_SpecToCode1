## MVP Guardrail: No Payment Affordances
To keep the MVP focused and compliant, this repo includes a non-functional, reflection-based test that fails the build if any payment-related terms appear in controller names, route templates, or action names.

- Test location: Tests/NonFunctional/NoPaymentEndpointsTests.cs
- Forbidden terms: payment, payments, billing, checkout, subscription, invoice, card, creditcard, stripe, paypal
- How to run locally: dotnet test

This guardrail ensures:
- No payment-related API endpoints can be introduced inadvertently.
- Swagger/OpenAPI produced from controllers will also be free of payment paths/tags by construction.

For frontend repos (web/mobile), remove any payment UI elements (links, buttons, forms). See specs/remove-payment-ui-elements for the functional spec and technical plan.
