## API Usage

### Email Registration Endpoint

#### `POST /api/auth/register`

Registers an email address for verification. This endpoint validates the submitted email and attempts to send a verification email to the provided address.

> **Note:** For this version, the endpoint does not persist any user accounts or track submissions. No roles, credentials, or user database are created at this stage. The focus is on format validation and issuing a verification email.

#### Request

**Body:**

```json
{
  "email": "user@example.com"
}
```

- **email** (string, required): The user's email address to register and verify.

#### Successful Response

**Status:** `200 OK`

```json
{
  "status": "Verification email sent"
}
```

- The API will always respond `200 OK` for a syntactically valid request, regardless of whether the email is registered/pending to avoid user enumeration. If an error occurs sending the email, see error formats below.

#### Invalid Email Format

**Status:** `400 Bad Request`

```json
{
  "error": "InvalidEmail",
  "message": "The provided email address is not valid.",
  "statusCode": 400,
  "timestamp": "2024-05-28T13:21:05.000Z"
}
```

- Email must be an RFC 5322-compliant address; whitespace-only, missing `@`, or obviously invalid formats are rejected.

#### Downstream Failure (Email Sending Error)

**Status:** `500 Internal Server Error`

```json
{
  "error": "EmailSendFailure",
  "message": "Failed to send verification email. Please try again later.",
  "statusCode": 500,
  "timestamp": "2024-05-28T13:22:19.000Z"
}
```

- The error is generic and never discloses whether a given address is in the system.

#### Error Response Format

All errors follow the `ErrorResponse` structure:

| Field      | Type    | Example                                             | Description                                           |
|------------|---------|-----------------------------------------------------|-------------------------------------------------------|
| error      | string  | "InvalidEmail"                                      | Short error code (e.g., InvalidEmail, EmailSendFailure)|
| message    | string  | "The provided email address is not valid."          | Human-readable description                            |
| statusCode | int     | 400                                                 | HTTP status code                                      |
| timestamp  | string  | "2024-05-28T13:21:05.000Z"                          | UTC ISO-8601 time the error was produced              |
| details    | string? | (optional)                                          | Extra details (internal/logging only, usually omitted)|

#### Security & Anti-Abuse

- The API does **not** indicate if an email is new, in use, or pending. No user enumeration.
- Invalid emails are rejected before any delivery attempt.
- All email submissions are subject to validation and audit logs (in production).

#### Email Verification Notes

- In this version, the verification email sending is mocked: emails are not actually delivered.
- For demonstration/testing, the "sent" email can be found in logs (see developer console or logfile output).
- No verification tokens or links are persisted.
- Future versions are intended to support token/account lifecycle, rate limiting, and anti-abuse.

#### Extensibility & Configuration

- The email sending service can be swapped with a real SMTP/transactional provider by implementing the `IEmailSender` interface and registering it in dependency injection.
- The email format validator is modular and can be extended for custom policy.
- Error payloads are derived from a common model to simplify integration and error handling.

#### Example: cURL

**Valid Submission**

```sh
curl -X POST https://localhost:7000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{ "email": "test.user@mydomain.com" }'
```

**Response:**
```json
{
  "status": "Verification email sent"
}
```

**Invalid Submission**

```sh
curl -X POST https://localhost:7000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{ "email": "bad@address@foo" }'
```

**Response:**
```json
{
  "error": "InvalidEmail",
  "message": "The provided email address is not valid.",
  "statusCode": 400,
  "timestamp": "2024-05-28T13:21:05.000Z"
}
```
