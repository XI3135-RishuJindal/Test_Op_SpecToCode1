## User Registration Form (US-001)

### Purpose
The registration form provides a simple, accessible UI for first-time users to sign up for an account. It presents labeled input fields for **Full Name**, **Email Address**, and **Password**, and is designed to be usable by all users regardless of device or ability.

### Location

| Resource | Path |
|---|---|
| URL (Development) | `http://localhost:5000/Register` |
| URL (HTTPS Development) | `https://localhost:7000/Register` |
| Razor Page markup | `Pages/Register.cshtml` |
| Razor Page code-behind | `Pages/Register.cshtml.cs` |
| Stylesheet | `wwwroot/css/register.css` |
| Tests | `Tests/Controllers/RegisterPageTests.cs` |

To access the form locally:
1. Run the application: `dotnet run`
2. Open your browser and navigate to `http://localhost:5000/Register`

### Form Fields

| Field | Input Type | Label Text |
|---|---|---|
| Full Name | `text` | Name |
| Email Address | `email` | Email |
| Password | `password` | Password |

### Accessibility Features
The registration form is implemented to meet **WCAG 2.1 AA** standards:

- **Semantic HTML**: Uses `<form>`, `<label>`, `<input>`, and `<button>` elements for correct structure and screen reader compatibility.
- **Programmatically associated labels**: Every `<input>` has a corresponding `<label>` linked via matching `for` / `id` attributes, ensuring screen readers announce field names correctly.
- **Keyboard navigation**: All form controls are reachable and operable via the keyboard using the Tab key. Tab order follows the visual layout (Name → Email → Password → Submit).
- **ARIA attributes**: `aria-required="true"` is set on all fields to communicate required status to assistive technologies.
- **Responsive layout**: The form renders correctly on screen widths from 320 px (mobile) to 1200 px and above (desktop), using a fluid CSS layout defined in `wwwroot/css/register.css`.

### Limitations
> **This is a static, UI-only implementation.**

- **No backend logic**: Submitting the form does not create a user account, call any API, or persist any data.
- **No input validation**: Field-level validation (e.g., email format, password strength) is out of scope for this story and will be addressed in a future iteration.
- **No error or success feedback**: The form does not display validation errors or a success message upon submission.
- **No authentication integration**: The registration form is independent of the JWT authentication system used by the API Gateway endpoints.
