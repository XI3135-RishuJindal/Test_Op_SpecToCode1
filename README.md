## SSO Registration Setup Instructions

The SSO (Single Sign-On) registration feature allows users to register and log in using their credentials from external Identity Providers (IdPs) such as Okta, Auth0, Azure AD, or Google Identity. Below are the instructions to set up SSO for different environments.

### Configuration Requirements

1. **Environment Configuration:**
   - Ensure that your environment JSON configuration files (e.g., `appsettings.json`, `appsettings.Development.json`) contain the following sections:
     ```json
     "Authentication": {
       "IdpProviders": {
         "Okta": {
           "ClientId": "<Your_Okta_Client_Id>",
           "ClientSecret": "<Your_Okta_Client_Secret>",
           "Authority": "https://<Your_Okta_Domain>/oauth2/default"
         },
         "Auth0": {
           "ClientId": "<Your_Auth0_Client_Id>",
           "ClientSecret": "<Your_Auth0_Client_Secret>",
           "Authority": "https://<Your_Auth0_Domain>/"
         },
         "AzureAD": {
           "ClientId": "<Your_Azure_AD_Client_Id>",
           "TenantId": "<Your_Tenant_Id>",
           "Authority": "https://login.microsoftonline.com/<Your_Tenant_Id>"
         },
         "Google": {
           "ClientId": "<Your_Google_Client_Id>",
           "ClientSecret": "<Your_Google_Client_Secret>",
           "Authority": "https://accounts.google.com/"
         }
       }
     }
     ```

2. **Secure Token Transmission:**
   - Ensure all token exchanges are performed over SSL/TLS. This typically involves configuring your application server to support HTTPS.

3. **Client Id and Secrets:**
   - Store all client IDs and secrets securely, utilizing environment variables or secret management tools to protect these credentials in all deployment environments.

### Steps to Configure SSO

#### Development Environment

1. Update `appsettings.Development.json` with instance-specific IdP details as indicated above.
2. Run your application in Development mode ensuring all endpoints are accessible and perform authentication/authorization flows through IdP-local endpoints.

#### Production Environment

1. Update `appsettings.json` with live ClientId, ClientSecret, and Authority URLs provided by your IdPs.
2. Use a secure vault or environment management tool to store Client Secrets and related sensitive information.

### Common Setup for all IdPs

- **Redirect URIs**: Register redirect URIs in your IdP configuration to include `https://<your-app-domain>/signin-oidc`.
- **Scopes**: The common OIDC scopes to include are `openid`, `profile`, and `email`.
- **Logout Redirect URI**: Optionally, configure a logout redirect URL to manage logout endpoints across multiple IdPs.
